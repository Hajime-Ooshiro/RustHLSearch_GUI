# RustHLSearch

HLSearch（素数シフト探索）の Rust 実装です。指定した深さまでの素数シフト列をビームサーチし、葉のビット数（popcount）の最大値と、その最大値を持つシフトパスを記録します。

## 機能・特徴

- **高速なビット並列処理**: 64-bit 単位の独自 `BitMask` 構造体による bitwise AND および popcount。
- **全候補展開ビームサーチ**: 枝刈りを通過した候補を各深さで全て次の深さへ展開。
- **割り当てを抑えたビット演算**: 深さごとの作業バッファを再利用し、AND 演算と popcount を1回の走査で実行。
- **固定ターゲットによる枝刈り**: `State` の固定ターゲット値 `447` 未満となった枝を打ち切る。
- **降順探索**: 各素数のシフト候補を降順（$p-1 \dots 0$）に探索。
- **GUI による探索と可視化**: TopView で探索深さを指定して検索を実行し、MainView に最大スコアを持つ探索パスを木グラフで表示します。グラフはスクロールできます。
- **進捗表示**: 探索をバックグラウンドで実行し、GUIを操作可能なままノード数、最良値、ヒット数、現在深さ、経過時間を表示する。探索指標はチェックポイント保存周期ごとに更新する。
- **チェックポイント再開**: 100,000 ノードごとに進捗を更新し、現在のビームと展開位置を `--output-dir` 配下の `checkpoint.json` へ保存・再開可能。探索が正常終了すると `checkpoint.json` と `checkpoint.bak` を削除します。

## ビルド

### Cargo によるビルド

```bash
cargo build --release
```

バイナリは `target/release/hlsearch`（Windows では `target/release/hlsearch.exe`）に出力されます。

### Windows 用バッチファイル

Windows 環境向けに `build.bat` も用意されています（デバッグビルドおよびリリースビルドを順に実行）。

```cmd
build.bat
```

## ソース構成

```text
src/
  main.rs      # GUI、CLI解析、入力検証、探索実行
  bitmask.rs   # BitMaskによる64-bit単位のビット演算
  primes.rs    # エラトステネスの篩による素数生成
  search.rs    # シフトテーブル生成、ビームサーチ、チェックポイント
  rocksdb_output.rs # RocksDB による親ノード形式シフトパス永続化
```

## 実行

ヘルプの表示:

```bash
cargo run --release -- --help
```

### GUI の起動と操作

```bash
cargo run --release
```

起動後、TopView の Depth 欄に探索する深さを入力し、Search ボタンを押します。探索完了後、MainView に最大スコアと、そのスコアを持つシフトパスをまとめた探索木を表示します。ノードはシフト値を表し、葉にはスコアが表示されます。パス数が多い場合は MainView 内をスクロールして確認できます。BottomView は MainView の下に配置され、直近500件のログを表示します。

Depth は 1 以上、利用可能な素数数以下である必要があります。無効な値や検索中のエラーは TopView に表示されます。

### コマンドライン引数の例

デフォルト（並列モード、深さ 8、cols 3159）:

```bash
cargo run --release
```

逐次モード（単一スレッド）で実行:

```bash
cargo run --release -- --mode sequential --depth 8
```

逐次探索では `--output-dir`（既定はカレントディレクトリ）配下に `checkpoint.json` を自動保存・再開します:

```bash
cargo run --release -- --mode sequential
```

並列探索も同じファイルへチェックポイントを保存し、同じコマンドで再開できます:

```bash
cargo run --release -- --mode parallel
```

探索中は 100,000 ノードごとに進捗を更新し、ビームの状態と集計値を `--output-dir`（既定は `.`）配下の `checkpoint.json` に自動保存します。実行中に `Ctrl+C` を1回押すと、安全な探索地点で同じチェックポイントを保存して終了します。次回は同じ設定で起動すると中断地点から再開できます。シフトパスとターゲット一致パスは `HLSearch.rocksdb` に保存され、再開時にそこから復元します。更新前の世代は同じディレクトリの `checkpoint.bak` に退避されます。起動時に `checkpoint.json` が存在しない場合は `checkpoint.bak` から復旧を試みます。GUI からの探索が正常終了すると `checkpoint.json` とバックアップを削除します。中断時は再開用に残します。逐次チェックポイントは `--mode sequential` でのみ、並列チェックポイントは `--mode parallel` でのみ再開できます。

探索開始時、同じ `HLSearch.rocksdb` に前深さの保存済みパスがあれば、そのパスを開始パスとして再利用します。前深さのパスが存在しない場合、または深さ 1 の保存済みパスが存在しない場合は、先頭レベルから探索します。

探索中はGUIを応答可能な状態に保ち、ノード数、最良値、ヒット数、現在深さ、経過時間を表示します。総探索ノード数は探索中に確定しないため、完了率や残り時間は表示しません。探索指標はチェックポイント保存周期ごとに更新され、完了時に結果表示へ切り替わります。`INFO` レベル以上のログはGUI内と標準エラーに表示され、`--output-dir` 配下の `hlsearch.log` に追記されます。ログファイルは起動時に切り詰めず、過去の実行ログを保持します。

チェックポイント保存周期を変更する場合:

```bash
cargo run --release -- --checkpoint-interval 50000
```

`--checkpoint-interval` でノード数を指定できます（デフォルト: 100,000）。逐次・並列のどちらでも有効です。

深さ、列数、出力先を指定して実行:

```bash
cargo run --release -- --depth 10 --cols 4000 --output-dir results
```

> **Note**: 現在は逐次・並列の両モードで同じ決定論的なビームサーチを実行します。モードは既存のCLI互換性とチェックポイントの再開検証のため維持されています。

### 入力値の検証

実行開始前に次の条件を検証します。条件に違反した場合はエラーを表示して終了します。

- `depth` は 1 以上
- `cols` は 1 以上
- `checkpoint-interval` は 1 以上
- `depth` は使用する素数数以下

## 探索アルゴリズムの概要

1. **素数生成**:
   - 1579 以下の素数（最大 249 個）をエラトステネスの篩で生成し、先頭から `depth` 個を探索階層に使用します。
2. **補集合シフトテーブル作成**:
   - 各素数 $p$ とシフト $k \in [0, p)$ について、長さ `cols` の補集合ビットマスクを事前構築します。
3. **ビームサーチ**:
   - 現在の全パスから次の素数のシフト候補を展開し、枝刈りを通過した候補をすべて保持します。
   - 累積 popcount が固定ターゲット値 `447` 未満となる候補は即座に除外します。
4. **葉ノード（深さ `depth`）の判定**:
   - ビームに残った葉から `max_score` とそのパスを記録します。

### 探索モード

- `--mode parallel`（デフォルト）: 既存のCLI互換性を保ったビームサーチです。
- `--mode sequential`: 単一スレッドのビームサーチです。

## コマンドラインオプション

| フラグ | 短縮 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `--depth` | `-d` | `8` | 探索する階層数（使用する素数の個数） |
| `--mode` | `-m` | `parallel` | 探索モード（`parallel` または `sequential`） |
| `--cols` | | `3159` | ビット列の長さ |
| `--output-dir` | `-o` | `.` | 出力ディレクトリ |
| `--checkpoint-interval` | | `100000` | チェックポイント保存周期 (ノード数) |

## 出力ファイル形式

探索中に枝刈りを通過したシフトパスは、`--output-dir` 配下の `HLSearch.rocksdb` に親ノード形式で保存されます。各ノードは親ノードへの参照、シフト値、スコアを持ち、共通の接頭辞は複数のパス間で共有されます。深さ 249 でターゲット値 447 に一致したパスは、ターゲットパス用のカラムファミリーにも保存されます。GUI の MainView には最高スコアのパスが木グラフで表示されます。探索結果自体は JSON やテキストのファイルには出力しません。ログは `hlsearch.log` にテキスト形式で記録されます。
